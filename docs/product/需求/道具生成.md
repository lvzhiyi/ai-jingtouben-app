## 1. 背景与问题

镜头预演的示意画面全部由客户端程序绘制，道具只内置了伞、黑伞和手机。剧本里出现素材库没有的东西（猫、吉他、篝火、行李箱……）时，画面里就没有它，预演和剧本对不上，题材越偏差距越大。

靠开发者逐个往素材库里加道具，永远追不上用户写的剧本。

## 2. 目标

- 剧本里出现的常见道具，预演里都能画出来，不受内置素材库限制。
- 只用现有的文本模型，不接入付费的图片、视频生成模型。
- 生成的道具和现有画面是同一种手绘风格。
- 生成过的道具在本机缓存，任何剧本再用到都不重复调用模型。
- 生成慢或失败都不影响预演播放。

### 不做（本期）

- 整幅场景、建筑、室内布局的生成：场景仍用现有 7 种模板。
- 人物外形（服装、发型）的生成。
- 道具动画（猫走动、火焰跳动）：道具是静态的，只跟着运镜动。
- 跨设备共享道具缓存（第一版没有账号和云同步）。
- 用户手绘或上传道具图片。

## 3. 用户与场景

- 用户写了一个带宠物猫的故事，分镜生成后直接预演，画面里林夏身边有一只猫。
- 用户写古风或奇幻剧本，道具（灯笼、长剑、信纸）能画出来；场景仍是通用模板。
- 某个道具画得不像，用户点「重画」，换一个版本。

## 4. 功能需求

### 4.1 道具从哪来

分镜生成时，模型在每个镜头里多输出一个 `props` 字段，列出画面里需要出现的道具和归属：

```json
"props": [{"name": "猫", "owner": null}, {"name": "吉他", "owner": "陈默"}]
```

- `owner` 为出场角色名表示拿在这个人手里或在他身边；为 `null` 表示放在场景里。
- 道具名要简短、具体（「吉他」而不是「一把旧木吉他」），一个镜头最多 3 个。
- 旧数据和模型没给 `props` 时，沿用镜头预演 4.3.1 的关键词匹配。

### 4.2 内置道具优先

伞、黑伞、手机继续用内置画法（和木偶人的手部姿态绑定）。其余道具先查本机缓存，没有再请求生成。

### 4.3 生成：受限的绘图 JSON

客户端把没缓存的道具名分批发给服务端（每批最多 5 个），服务端用文本模型生成，流式返回。只发道具名，不发故事、画面描述和对白。

每个道具的输出格式：

```json
{
  "name": "吉他",
  "anchor": "hand",
  "size": 0.6,
  "grip": [0.5, 0.2],
  "shapes": [
    {"t": "ellipse", "x": 0.5, "y": 0.72, "w": 0.55, "h": 0.4, "fill": "light"},
    {"t": "polyline", "pts": [[0.5, 0.05], [0.5, 0.6]]}
  ]
}
```

| 字段 | 含义 |
| --- | --- |
| `anchor` | 放在哪：`hand`（拿在手里）、`ground`（地上）、`table`（桌上）、`wall`（墙上） |
| `size` | 道具高度相对人身高（人 = 1） |
| `grip` | 仅 `hand`：手握的位置（0–1 方框坐标） |
| `shapes` | 从后到前的图形列表，坐标在 0–1 方框内，x 向右、y 向下 |

图形只允许 6 种：`line`、`polyline`、`polygon`、`circle`、`ellipse`、`arc`。填充只允许 `none`、`light`、`mid`、`dark`、`accent` 五档，映射到预演配色，保证风格统一、夜景深色模式也能看。

### 4.4 校验

客户端收到后逐个校验，不合格整个道具丢弃、按失败处理：

- 图形类型和填充值在白名单内；`polygon` 3–12 个点，`polyline` 2–16 个点。
- 每个道具 1–30 个图形；所有坐标、半径在 −0.05–1.05 之间。
- `size` 在 0.03–1.5 之间；`anchor` 合法；`hand` 必须有 `grip`。
- 只解析数据，不执行任何模型输出的代码，也不接受 SVG 原文。

### 4.5 摆放

| anchor | 摆放 |
| --- | --- |
| `hand` | `grip` 对齐到木偶人空着的那只手（伞占左手、手机占右手时依次让位；两只手都占用时改放脚边） |
| `ground` | 有 `owner` 时放在这个人脚边外侧，否则放在人物层的空位；远景到全景能看到 |
| `table` | 本期按 `ground` 处理（Q4）；后续在室内画一张简易桌子放在上面 |
| `wall` | 本期按 `ground` 处理（Q4）；后续在室内画在中景层墙上 |

- 道具和人物在同一层，跟着运镜动、按景深虚化。模型仍按四种 `anchor` 输出，后续加桌面、墙面摆放时不用改提示词。
- 画面截到身上的景别（中景以上）里，脚边的道具在画框外就不画；手里的道具按手的位置决定。
- 画面截到身上的景别里，属于某人的 `table` 道具改为举在胸前（v0.3）：每人一个，用空着的手托着（先右手，右手拿手机或在挥手时用左手，两只手都占用时仍按脚边处理）。道具最多占画框宽度的六成；特写里胸口在画框外时往上挪到至少露出七成，但不高过下巴。还没画好的道具不举，避免占位方块先举起、画好后又换到脚边。

### 4.6 生成中与失败

- 预演不等生成：没画好的道具先画一个带名字的手绘小方块，画好后下一帧替换。
- 失败（超时、校验不通过、限流）也画占位方块，镜头卡不报错；同一道具当天不自动重试，可手动重画。
- 每个剧本最多为 10 个新道具调用模型（Q5，已缓存的不计），超出的按出现顺序显示占位方块，可手动重画逐个补。

### 4.7 重画

预演页长按道具（或道具占位）弹出「重画这个道具」，重新生成一个版本直接覆盖缓存，不提供多候选（Q3）。重画后所有用到这个道具的剧本一起更新。

## 5. 数据与接口变更

### 5.1 本地表（drift）

新增 `prop_drawings` 表，schemaVersion 3 → 4，补迁移步骤、`drift_schemas/` 快照和迁移测试：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `name` | text，主键 | 归一化后的道具名（去空格、全角转半角） |
| `drawingJson` | text，可空 | 校验通过的绘图 JSON |
| `status` | textEnum | `ready` / `failed` |
| `updatedAt` | dateTime | 生成或重画时间 |

镜头表新增 `propsJson`（text，可空），存 4.1 的道具列表。

### 5.2 模型输出

`server/src/storyboard/storyboard.prompt.ts` 的输出字段新增 `props`，解析时非法项丢弃并加 `warnings`（沿用 PV-R01 的做法，不落库）。

### 5.3 服务端接口

- 新增 `POST /props/draw`，请求体 `{ "names": ["猫", "吉他"] }`，1–5 个，每个不超过 10 个字。
- 返回流式文本（与分镜接口同一套 SSE 约定），客户端拼完后解析。
- 只做转发和限流，沿用设备限流；不缓存、不落库，日志不打印道具名和响应内容。
- 没配置 Key 时返回内置的模拟数据，本地开发不花钱。

### 5.4 提示词

绘图提示词和分镜提示词一样写在服务端代码里（`server/src/props/draw.prompt.ts`），不放进 `prompt_templates.json`：那两份文件是下发给客户端拼即梦 / 可灵视频提示词的模板，和这里无关。分镜提示词新增 `props` 字段的说明改在 `storyboard.prompt.ts`。

## 6. 非功能需求

- **速度**：实验中 10 个道具一次请求约 127 秒；本期按每批 5 个、最多 2 批并行，一个新剧本首次预演时道具在 1 分钟内补齐。必须用流式请求：实验中的中转网关对非流式请求 60 秒超时。
- **成本**：一个道具约 1000 字符输出；每个剧本最多生成 10 个新道具；有本机缓存后同一道具只花一次。
- **性能**：每个道具最多 30 个图形，预演帧率要求不变（见镜头预演第 6 节）。
- **隐私**：只上传道具名。
- **安全**：只解析白名单内的数据结构，不执行模型输出。

## 7. 验收标准

1. 新生成的分镜带 `props`；旧数据仍按关键词显示内置道具。
2. 预演中第一次出现的道具先显示占位方块，生成后自动替换；失败时保持占位，预演不中断。
3. 同一道具第二次出现（同剧本或其他剧本）不再请求服务端。
4. 拿在手里的道具对准手的位置；伞、手机和生成道具同时存在时手不冲突。
5. 道具跟随运镜、景深，与画面风格一致；深色主题和夜景下可见。
6. 不合格的绘图 JSON 被丢弃，有单测覆盖每条校验规则。
7. 重画后缓存更新，所有剧本里的这个道具一起变化。
8. 两份视频提示词模板不受影响，CI 比对仍通过；app 覆盖率不低于 85%，server 测试通过。

## 9. 可行性实验（2026-11-07）

- 方法：用当前配置的文本模型，按 4.3 的格式（当时未含 `grip`）一次生成猫、咖啡杯、自行车、篝火、书、花束、行李箱、吉他、狗、蛋糕 10 个道具，再用预演的 `SketchPen` 渲染。
- 结果：10 个全部通过 4.4 的校验（每个 8–26 个图形，无越界）；渲染后都能一眼认出，自行车车架略歪；`anchor` 和 `size` 给得合理（猫 0.28、放地上；咖啡杯放桌上；吉他拿在手里）。
- 耗时：流式请求约 127 秒、约 1.1 万字符；非流式请求被中转网关 60 秒超时。
- 实验脚本和图在会话临时目录，未进仓库。
